# 소셜 화면 패턴

## 요약

이 문서는 공개 소셜 라우트와 그 인증 경계에 대한 현재 UX 패턴을 정의합니다. 사용자에게 보이는 소셜 화면을 구현하거나 리뷰할 때 이 문서를 기준으로 삼습니다.

## 패턴: 공개 피드

- `/feed`는 비로그인 사용자와 로그인 사용자 모두의 첫 진입 라우트다.
- 게스트 피드는 읽기 중심의 메인 컬럼 하나로 유지해야 하며, 탐색용/홍보용 셸로 쪼개지지 않아야 한다.
- 게스트 `/feed`는 현재 제품 단계에서 실시간 전체 공개 피드를 그대로 노출해야 하는 화면으로 간주하지 않는다.
- 초기 게스트 `/feed`는 privacy-safe한 큐레이션 프리뷰 또는 제한된 목 데이터를 사용할 수 있다.
- 이후 게스트 `/feed`는 추천 알고리즘 또는 인기 게시글 정책이 준비되면, 추천/인기 기반 공개 피드로 확장할 수 있다.
- 게스트 피드에는 콘텐츠를 샘플, 데모, 미리보기 전용으로 규정하는 라벨을 쓰지 않는다.
- 프리뷰 화면이라면, 아래 규칙을 따른다:
  - 실제로 동작하지 않는 해시태그, 프로필, 액션을 클릭 가능한 affordance처럼 보이게 두지 않는다.
  - fake viral count나 실시간 전체 커뮤니티처럼 오인될 수 있는 연출은 피한다.
  - 로그인 전에는 얕은 탐색만 허용하고, 더 깊은 탐색이나 상호작용은 인증 경계에서 끊는다.

## 패턴: 공개 게시글 상세

- 게시글 자체가 공개라면 `/posts/:id`는 직접 읽을 수 있어야 한다.
- 게시글 상세는 이미지, 연결된 워크아웃, 댓글, 액션이 한 문서 흐름처럼 이어져야 한다.
- 게스트 사용자는 로그인 없이도 페이지를 읽을 수 있어야 한다.
- 게스트가 좋아요, 댓글, 보호된 워크아웃 상세 진입을 시도할 때는 온페이지 인증 다이얼로그를 열고 현재 게시글 URL을 유지해야 한다.

## 패턴: 공개 크루 탐색

- `/crews`는 로그아웃 상태 방문자에게 공개 탐색 화면으로 먼저 동작해야 한다.
- 게스트 사용자는 `/login`으로 튕기지 않고 공개 크루를 둘러볼 수 있어야 한다.
- 명확히 멤버 전용인 영역으로 들어가려 할 때만, 갑작스러운 페이지 이동 대신 인증 다이얼로그를 띄운다.

## 패턴: 공개 크루 상세

- 크루가 공개라면 `/crews/:id`는 로그인 없이 읽을 수 있어야 한다.
- 기본 크루 정보, 활동 목록, 게시판 목록은 로그인 전에도 읽을 수 있어야 한다.
- 활동 상세, 게시판 게시글, 크루 게시글, 채팅, 가입 완료 뒤 멤버 전용 기능은 로그인 또는 멤버십 경계에서 막아야 한다.
- 게스트가 목록 항목에서 더 깊은 읽기를 시도할 때는 현재 크루 URL을 유지한 채 온페이지 인증 다이얼로그를 연다.

## 패턴: 공개 프로필 상세

- `/profile/:id`는 공개 라우트 트리에 속한다.
- 공개 계정의 `/profile/:id`는 로그인 없이 직접 읽을 수 있어야 한다.
- 공개 프로필의 기본 읽기 표면은 헤더, 게시글 탭, 크루 탭이다.
- 타인 공개 프로필에서는 workout 표면을 노출하지 않는다. workout 상세 visibility와 별개로, 프로필 라우트에서는 위치 민감도를 이유로 보수적으로 다룬다.
- 이 보수 정책은 web 탭 숨김뿐 아니라 profile API 계약에도 반영된다. 타인 프로필 응답은 workout aggregate를 surface truth로 취급하지 않는다.
- 팔로워/팔로잉 수치는 헤더에서 읽을 수 있어도, 목록 라우트 자체는 공개 탐색 표면으로 열지 않는다.
- 비공개 계정 direct link는 잠긴 프로필 셸로 다뤄야 하며, 최소 정체성만 보여주고 콘텐츠 탭과 사회적 수치는 기본적으로 감춘다.

## 게스트 공개 정책 매트릭스

| 라우트          | 게스트 현재 정책                       | 로그인 요구 시점                           | 비고                                                            |
| --------------- | -------------------------------------- | ------------------------------------------ | --------------------------------------------------------------- |
| `/feed`         | 큐레이션 프리뷰 또는 제한된 목 데이터  | 더 깊은 탐색, 상호작용, 향후 개인화 추천   | 초기에는 실시간 전체 공개 피드가 아님                           |
| `/posts/:id`    | 공개 게시글 직접 읽기 허용             | 좋아요, 댓글, 보호된 워크아웃 진입         | 공유 가능한 공개 객체 역할                                      |
| `/crews`        | 공개 크루 탐색 허용                    | 내 크루, 가입, 채팅, 활동 진입             | 크루 단위 유입을 우선                                           |
| `/crews/:id`    | 공개 크루 요약 + 활동/게시판 목록 허용 | 가입, 상세 읽기, 채팅, 멤버 전용 기능 진입 | deeper read는 route 유지형 auth gate로 차단                     |
| `/profile/:id`  | 공개 프로필 직접 읽기 허용             | 팔로우, 메시지, 보호된 팔로우 목록 진입    | 헤더 + 게시글 + 크루만 공개, workout surface와 aggregate는 숨김 |
| `/workouts/:id` | 현재는 보호 라우트 유지                | 상세 진입 시점                             | 공개 post 안에서는 preview + 모달 게이트를 사용                 |

## 패턴: 인증 유도

- 인증 다이얼로그는 실제 결과가 달라지는 순간에만 나타나야 한다.
- 제목은 서비스 홍보가 아니라, 지금 막힌 행동이 무엇인지 말해야 한다.
- 기본적으로는 제목만으로 충분해야 하며, 설명 본문은 복귀 보장이나 공개 범위 경계를 알려야 할 때만 예외적으로 추가한다.
- 인증 유도는 현재 라우트를 `next`로 보존해야 한다.
- 다이얼로그를 닫으면 사용자는 방금 있던 위치에 그대로 남아 있어야 한다.

## 패턴: 뒤로가기

- 사용자가 공개 라우트에서 다이얼로그를 열었다면, 브라우저 뒤로가기는 underlying route를 떠나기 전에 먼저 그 overlay 상태를 되감아야 한다.
- 대상 라우트 자체가 보호된 화면이 아닌 이상, 공개 탐색 흐름이 `/login?next=...`에 갇혀서는 안 된다.
- 대상 라우트가 보호된 화면이라면, `next`는 원래 목적지를 정확히 보존해야 한다.
