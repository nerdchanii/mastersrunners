## 1. 검수 목적

- 크루 채팅, 활동 채팅, DM, unread badge 동기화가 브라우저에서 자연스럽게 동작하는지 확인한다.
- `I-0009-010`의 UX 개선 사항이 실제 사용자 흐름에서 어색함 없이 연결되는지 확인한다.
- `I-0009-020`의 회귀 방지 범위가 실제 수동 검수 시나리오와도 일치하는지 확인한다.

## 2. 검수 환경

- 웹 앱과 API가 로컬에서 실행 중이다.
- API 기본 주소는 `http://localhost:4000/api/v1`이다.
- 브라우저 DevTools를 사용할 수 있다.
- 모바일 검수는 브라우저 device toolbar 또는 동등한 반응형 모드로 수행한다.

## 3. 사전 조건

- 로그인 가능한 계정이 최소 2개 있다.
- 검수용 크루 1개, 활동 1개, DM 대화 1개가 준비되어 있다.
- 본인 계정이 아래 상태를 확인할 수 있다.
  - 크루 멤버 상태

  - 활동 비참석 상태

- 전송 실패 UX 확인은 브라우저 DevTools Network를 `Offline`으로 전환해 재현한다.

## 4. 인수확인 체크리스트

### 4.1 크루 채팅 UX

| 체크 항목                                                                        | 결과 | 메모 |
| -------------------------------------------------------------------------------- | ---- | ---- |
| `/crews/:crewId` 진입 후 hero의 대화 아이콘이 멤버에게 노출된다.                 |      |      |
| 대화 화면 헤더가 일반 ID가 아니라 자연스러운 크루명 기반 문구로 보인다.          |      |      |
| 참여자 수가 함께 표시된다.                                                       |      |      |
| 입력 placeholder가 크루 맥락 문구로 보인다.                                      |      |      |
| 빈 채팅일 때 첫 메시지 유도 문구가 자연스럽다.                                   |      |      |
| 새 메시지 전송 시 화면 하단으로 자연스럽게 이어지고 스크롤이 과하게 튀지 않는다. |      |      |
| 읽는 중 폴링 갱신이 발생해도 이전 메시지를 읽기 어렵게 만들지 않는다.            |      |      |
| 네트워크 실패 시 draft가 유지된다.                                               |      |      |
| 네트워크 실패 시 인라인 오류가 보인다.                                           |      |      |

### 4.2 활동 상세 진입 CTA

| 체크 항목                                                                                                  | 결과 | 메모 |
| ---------------------------------------------------------------------------------------------------------- | ---- | ---- |
| `/crews/:crewId/activities/:activityId`에서 `RSVP`, `CHECKED_IN`, 운영 권한 사용자에게 대화 버튼이 보인다. |      |      |
| 비참석 사용자에게는 대화 버튼이 보이지 않는다.                                                             |      |      |
| 버튼 클릭 시 `/crews/:crewId/activities/:activityId/chat`으로 이동한다.                                    |      |      |

### 4.3 활동 채팅 UX

| 체크 항목                                                                               | 결과 | 메모 |
| --------------------------------------------------------------------------------------- | ---- | ---- |
| 참석 가능 사용자가 활동 채팅 페이지에 진입하면 제목이 `활동명 활동 채팅` 형태로 보인다. |      |      |
| 부제와 안내 문구가 활동 맥락에 맞다.                                                    |      |      |
| 입력 placeholder가 활동명 기반 문구다.                                                  |      |      |
| 빈 채팅 상태에서 첫 메시지 유도 문구가 자연스럽다.                                      |      |      |
| 비참석 사용자가 직접 URL로 진입하면 입력창 대신 설명 카드가 보인다.                     |      |      |
| 설명 카드에 활동 상세로 돌아가는 액션이 있다.                                           |      |      |
| 활동 상세 CTA 노출 규칙과 활동 채팅 직접 진입 규칙이 서로 모순되지 않는다.              |      |      |

### 4.4 DM 상세 UX

| 체크 항목                                                                        | 결과 | 메모 |
| -------------------------------------------------------------------------------- | ---- | ---- |
| `/messages` 진입 시 메시지 목록이 정상적으로 보인다.                             |      |      |
| `/messages/:conversationId` 진입 시 상대 이름과 메시지 내역이 정상적으로 보인다. |      |      |
| DM 전송이 정상 동작한다.                                                         |      |      |
| 네트워크 실패 시 draft가 유지된다.                                               |      |      |
| 네트워크 실패 시 인라인 오류가 보인다.                                           |      |      |

### 4.5 Unread Badge 동기화

| 체크 항목                                                                        | 결과 | 메모 |
| -------------------------------------------------------------------------------- | ---- | ---- |
| 데스크톱에서 `/messages` 진입 시 헤더 메시지 badge가 숨겨진다.                   |      |      |
| 모바일 뷰에서 `/messages` 진입 시 하단 네비 메시지 badge가 숨겨진다.             |      |      |
| 메시지 화면 밖에서 새 DM 수신 시 badge가 증가한다.                               |      |      |
| `/messages` 또는 `/messages/:id` 진입 후 읽음 처리되면 badge가 사라진다.         |      |      |
| 다른 화면으로 다시 이동해도 badge 상태가 모순 없이 유지된다.                     |      |      |
| 가능하면 `/notifications`에서도 현재 라우트에서 badge 숨김 동작을 함께 확인한다. |      |      |

### 4.6 회귀 확인

| 체크 항목                                                        | 결과 | 메모 |
