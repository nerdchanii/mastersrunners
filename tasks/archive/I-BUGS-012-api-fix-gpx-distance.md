## Goal

Resolve the GPX distance discrepancy by parsing native cumulative `<distance>` tags generated by watches inside GPX extensions, while falling back to Haversine only when cumulative distance is missing.

## Done Criteria

- The parser extracts native cumulative `distance` tags from supported GPX extension namespaces.
- The last point's positive cumulative distance is used as `totalDistance` when available.
- Backend parser-focused specs and API build typecheck pass.

## Notes

- This keeps GPX exports from Coros and Garmin aligned with the distance recorded on proprietary FIT exports.
- The parser still falls back to Haversine when cumulative distance is absent, so the change is additive rather than format-exclusive.
- Malformed extension numbers are normalized to `undefined` so bad GPX metadata does not poison aggregate stats with `NaN`.
